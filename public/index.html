Publish checklist

1. Export the candidate JSON and retain a copy of the previous version.

2. Have the client review and approve names, images, menu, prices, address and public contact details.

3. Update active-client.json through a reviewed GitHub pull request. Verify the preview and only then publish.

4. When a client gets a separate domain, archive the handover materials privately and replace the active demo with the next approved client.

ONE PUBLIC SLOT · UNLIMITED REUSE

A proposal space that renews for every client.

The APPTEST website remains on the same domain. Only the active prototype changes. Each finished client receives a separate website and domain, not a permanent slot on APPTEST.

Create a concept

Collect approved business details. Build a branded preview in the proposal studio and confirm that text and contact information are accurate.

Review with the client

Share the demo link, gather suggestions, revise the product/service experience, and record written approval before producing the real website.

Graduate to a domain

Build the real application in its own repository and domain. Add secure accounts, a real database, monitoring, backups and payment integrations only if contracted.

Archive the proposal privately

Download the concept JSON and record handover approval and client assets outside the public APPTEST repository. Never archive sensitive customer data in public Git history.

Replace the active demo

Switch the reviewed active-client.json to the next client. Delete unused public assets, invalidate relevant caches and confirm the old business is no longer displayed.

Repeat the sales cycle

APPTEST becomes an ongoing visual portfolio and lead-generation platform for MABRIG Technologies without locking clients into the demo domain.

IMPORTANT LIMITATION

A deleted preview can remain in Git history.

Replacing the demo removes it from the current public site, not necessarily Git history, CDN caches or saved bookmarks. Only publish details approved for public demonstration; use private storage for confidential material.

Launch gates for every client

Approved content → tested mobile flows → secure admin and database → privacy and payment reviews → domain / SSL → rollback and backups → owner handover.
